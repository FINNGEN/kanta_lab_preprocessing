# qc_checks

Value QC on the engine output: per test and service provider (`sp_qc.py`), per OMOP concept with the reference ranges (`omop_ref_audit.py`), a static portal over both (`qc_portal.py`), and the engine's `omop_qc.tsv`.

## Main

**`omop_ref_audit.py`**: audits OMOP IDs with the reference ranges: which rows went wrong in injection or harmonization, how, and what their unit should be. Each row's value, reference range and unit are checked against each other:

1. unit vs range: the range, converted with the row's harmonization factor, against the concept's canonical range (learned per sex × age group from the rows where everything agrees)
2. value vs range: the value against its own range, which needs no unit
3. value vs unit: the harmonized value against the concept median

Together they give a verdict per row: `ok`, `wrong unit` (value and range agree, the unit doesn't), `range off scale`, `value mis-scaled`, `value extreme`, `inconsistent` (the range differs from the others, the value is fine: often another assay), or, for rows without a harmonized value, `unharmonized: fixable` and the like. Each test name's harmonized values are also KS-tested against the rest of the concept (D ≥ `--ks-d`, 0.3): a high D with few rows flagged is another analyte or specimen on a similar scale, which the scale checks miss. A wrong unit gets a suggested unit from the conversion table: the unit whose factor puts the range on the canonical one. Rows without a range (`value off (no range)` when off by a unit factor, `unharmonized: no range`) get one from the value alone: the unit that brings it to the concept median, a weaker hint. Each flagged group also gets the stage its unit came from: lab, injected, rewritten (injection changed it) or no unit.

```
python3 omop_ref_audit.py --omop 3019550,3020564 | --all [--min-rows N]  [--input <engine_output>.parquet] [--out-dir DIR] [--cache DIR]
python3 omop_ref_audit.py 3019550          # one OMOP, as before
```

`--input` defaults to the most recent run in `/mnt/disks/data/kanta/engine`; reports go to `/mnt/disks/data/kanta/qc/omop` (`sp_qc.py` writes next to it, in `qc/sp`). The rows come from `sp_qc.py`'s row cache (`/mnt/disks/data/kanta/tmp/sp_qc/rows_<input name>/omop=<id>/`, shared: the OMOPs not cached yet are extracted in batches, one pass over the input per `--extract-batch` OMOPs), so either script fills it for the other. Three cached steps per OMOP under `--cache/audit/omop=<id>/`: the groups (with a people sketch, rebuilt when the rows change), then the **tables** (the analysis and every table the outputs show, already gated; rebuilt when the groups or the parameters change), then the **figure**, drawn from those tables only (`--plots-only` redraws it). Writes `omop_3019550_ref_audit.png` and the same as a vector `.pdf` (the three checks per test, a decision map, verdicts per test, flagged rows per stage, the flagged groups), `_groups.tsv`, `_verdicts.tsv`, `_canonical.tsv` and `_tests.tsv` (the KS test per test name), and prints the flagged groups as Markdown. Every published number covers at least `--min-n` (5) **people**: a group under 5 people is `BELOW_THRESHOLD` without statistics, and within each test name × unit × harmonized unit the hidden groups together are none or ≥ 5 people (secondary suppression, so the portal's composition rows minus the shown groups give nothing away); verdict, stage and test counts sum shown groups only, `% rows` is a share of the shown rows; a test is KS-compared when it and the rest cover ≥ 5 people each, and its Q1 / Q3 need ≥ 5 people beyond them. In the figure, histogram bins are pooled with their neighbours until each covers ≥ 5 people and the tails pile into the edge bins; decision-map points under 5 people are left out. Values of 0 or below are a group of their own (`no value > 0`), so the groups add up to the rows. Several OMOPs per run (`--omop`, comma-separated, or `--all --min-rows N`); one OMOP's problem (e.g. no canonical range) skips it, not the run.

```
test   source -> unit -> harmonized  stage  verdict     rows  % rows  range (source scale)  median pre-harm.  median harmonized  range x  value x  suggested unit
b-hkr  % -> % -> %                   lab    wrong unit  6000  1.7     0.35-0.46             0.417             0.417              /100     /100     ratio
```

**`sp_qc.py`**: which service providers (SPs), and when, deviate from the national picture for an OMOP ID, and why. It needs nothing run before it. Each OMOP's rows are read from the engine output once and cached in `/mnt/disks/data/kanta/tmp/sp_qc/rows_<input name>/omop=<id>/` (one row per result with a value, only the columns it needs, the person hashed); the OMOPs not cached yet are read together in one pass (duckdb, a partitioned write, no sort). The cache is dropped and rebuilt only when the input file changes (or with `--force`). Each OMOP's aggregates are cached too. Each flag gets a likely cause: the test, unit, decimals, QC note or range source whose share changed most in the flagged period. The kinds of flag are:

- `shift`: an SP × year whose median, adjusted for sex and age, is off national
- `step`: a lasting change in an SP's monthly median, and whether its reference limit changed with it (method change) or not (drift); only over runs of consecutive months, and marked when it comes after a gap in the data
- `episode`: a run of odd months that returns to normal
- `outliers`, `qc_fail`, `person_jump` (values far from the same person's other values): rates against expected
- `range`: an SP whose typical reference limit, converted to the harmonized unit, is off national (adults); `range_change`: an SP's limit changed between years. The report writes the actual ranges out: national per sex × age, and each SP's own, with the share of its limits from the curated text table. An upper limit of 999, 9999, 99999… counts as none (some labs send it for one-sided ranges); a national limit is shown only when at least half the rows with limits carry it, and one-sided ranges are drawn as arrows
- `outcome`: `TEST_OUTCOME` disagrees with the row's own range

```
python3 sp_qc.py [--omop 3020564 3023602 ...] [--all] [--input <engine_output>.parquet] [--out DIR] [--cache DIR]
```

`--input` defaults to the most recent run in `/mnt/disks/data/kanta/engine` (a release file works too, without the missing-unit cause). By default (`--scale all`) every concept is analysed three times, on raw values and as multiples of each row's own upper (× ULN) and lower (× LLN) reference limit, and the PDF shows them one under the other: three heatmap rows per lab (raw blue-orange, × ULN purple-green, × LLN brown-teal) and three boxes per lab, each relative to its national median (raw off but × ULN not: the lab's assay or limits, not its values; × LLN shows the low side, e.g. HDL, holo-TC, sodium); a scaled run is left out of the PDF when under `--min-scaled` (5%) of the rows have that limit; the flag page lists all runs' flags with a `values` column, and `_sp_year.tsv` has `above_uln_pct` and `below_lln_pct`. `--scale raw`, `uln` or `lln` runs one alone (4-page PDF; `_uln` / `_lln` in the names). `--scale uln` (or `lln`) works on each value as a multiple of its own row's upper (lower) reference limit, so that labs on different assays compare (TPO-Ab, TSH, ferritin, B12-TC); rows without that limit are left out, outputs get `_uln` in their names, and the labs show the share of their rows above their own ULN. A step under `--scale uln` is a change the lab's limit did not follow. `--omop` defaults to the QC-thread concepts (creatinine, ALT, ferritin, HDL, TPO-Ab, TSH, holo-TC, CRP, sodium). Writes into `/mnt/disks/data/kanta/qc/sp` (next to `omop_ref_audit.py`'s `qc/omop`), per OMOP, `sp_qc_<omop>_<name>.pdf` (the concept name from LABfi without its bracketed part, e.g. `sp_qc_3020564_creatinine_in_serum_or_plasma.pdf`; page 1: the 10 labs with the most rows, page 2: the 10 most deviating other labs, each with its name, rows, median vs national per year and its values; page 3: adult reference ranges, women and men, of the top labs by rows and the most deviating others, sorted by the multiplier vs national, one row per lab: its limits per year (women pink, men blue; a step is a change) over the national range as a band, the limit values on the right, then upright bars of its typical ranges next to the national ones (grey); its ranges and multiplier under its name; page 4: when the labs take their samples (hour of the day, weekday); page 5 on: the flags, most important first, with a key to the kinds, what is seen in plain words (e.g. "81 of 265 values (31%) are extreme … nationally 0.05%") and the likely cause), `_flags.tsv`, `_sp_year.tsv`, `_ranges.tsv` and `_timing.tsv` (the last two from the raw run only). `SERVICE_PROVIDER` is a pseudonym in R15, so SPs are named by the organisation most of their rows' coding systems belong to (`CODING_SYSTEM_MAP`), plus the end of the pseudonym, except when that organisation has no region of its own (a private company such as Fimlab, a lab serving several regions such as NordLab) and the SP has one: then by the region (e.g. `Pirkanmaa …76628f`); the region as in `scripts/sote`'s `sp_region.tsv` (the top maakunta among rows whose organisation has one, `CODING_SYSTEM_MAAKUNTA`, with its share, and those rows' share; counts in `sp_orgs_mk.parquet` in the row cache, built once per input; the rule itself is `scripts/sote/region/sp_names.py`'s `Labels`, also a standalone script in the pipeline, and `--sp-names kanta_sp_names.tsv` takes its table instead of counting); every published number covers at least `--min-n` (5) **people**, a hard condition built into the aggregates: each cached aggregate row carries the 5 smallest distinct person hashes of its rows (a sketch that merges exactly for the "≥ 5 people" test), so every lab-year, share, flag, typical limit, cause and plotted quantile is gated on people, not rows. Below it: `BELOW_THRESHOLD`, or not shown. A share is shown only when the part and the rest are each nobody or ≥ 5 people; all count shares use the rows with a value as their base; hidden lab-years are left out of every total over years; range groups and hours / weekdays of a lab get secondary suppression; a burst of outliers, jumps or QC fails from fewer people is not flagged at all; a concept without a single lab-year of ≥ 5 people is skipped (no files). Each TSV is checked once more before it is written (no count of 1–4 rows, also in "k of n values" texts) and is not written if one slips through. Page 4 and `_timing.tsv` show when each lab takes its samples (share of rows per hour of the day, exactly 00:00 = probably a date without a time, and per weekday) and, for all labs, the median value per hour / weekday vs all (same sex and age); a change in a lab's time of day (e.g. times becoming 00:00) is also a likely cause.

```
kind  sp                      period        rows   effect  detail                                                         likely cause
step  Fimlab Laboratoriot Oy  from 2017-03  31022  /1.09   median /1.09 from 2017-03; upper limit changed too: method change?
```

**`run_qc_all.sh`**: runs `sp_qc.py` and `omop_ref_audit.py` over every OMOP with at least MIN_ROWS rows, in parallel and with a progress bar. First `sp_qc.py --all --prepare` extracts their rows into the shared row cache in one pass. Then one job runs per OMOP and script, `--jobs N` at a time (default 2), each with 1/N of the duckdb memory and threads. Each job writes its own log under `LOG_DIR/qc_all_<date>_<time>/`. With `--skip-done` (also a flag of both scripts), an OMOP whose report PDF is already there and newer than its cached rows is skipped, so after lowering MIN_ROWS only the new OMOPs run. It doesn't check whether parameters or code have changed since: in that case, run without it.
```
scripts/qc_checks/run_qc_all.sh [--skip-done] [--jobs N] [MIN_ROWS] [LOG_DIR]
```

**`qc_portal.py`**: a static QC portal over the reports of `sp_qc.py` and `omop_ref_audit.py`: a folder of HTML pages with inline SVG charts and the reports, to put on a shared server (no server code, no external libraries, works offline). It only collects: the concepts are those either script was run for, with at least `--min-rows` rows (default 0) and 5 people (fixed). Two stages (`--stage tables|site|all`):

- `tables`: per concept, from the shared row cache and the two scripts' TSVs, gated tables into `/mnt/disks/data/kanta/qc/portal_tables/omop_<id>/`, cached until the rows or the reports change: `summary.tsv` (people, rows, records per person, % with ≥ 2 records, % female, median age at test, test names / units / labs of ≥ 5 people, years, the audit's % flagged rows, sp_qc's flags by kind), `composition.tsv` (per test name × unit × harmonized unit: people, rows, % of rows, median harmonized value, % with a reference range, typical range, % H/L outcome, the audit's % flagged and KS D; groups under 5 people pooled into one row, with secondary suppression), `years.tsv` (rows per year, years pooled until each covers ≥ 5 people)
  - for the drawings: `audit_*.tsv` / `audit_meta.json` (the audit's cached, gated figure tables; histogram bins and map points as shares only), `lab_order.tsv` (the 20 largest and 20 most deviating labs, from sp_qc's lab-years) and `lab_values.tsv` (each of those labs' p5 / p25 / median / p75 / p95 relative to the national median, per run, from sp_qc's cached value bins, kept where ≥ 5 people lie beyond), `lab_limits.tsv` (the most common adult limit per year × sex, upper and lower, of every service provider in sp_qc's ranges table, from sp_qc's cached limits, shown where ≥ 5 people carry it; and the national one)
  - every table and page matches sp_qc's service providers by the pseudonym tail (…61b3c1), so reports written before a naming change show the current names; the Service Providers table and pages also give each one's region as in `sp_region.tsv` (maakunta, its share among the regional rows, and the regional rows' share; shown when that is at least 5%)
  - labs, over the results of every OMOP in the row cache (with `--all`, nearly all results; from `sp_qc.sp_composition`: SP × coding-system organisation × year with people sketches, one pass over the cached rows, cached next to them and rebuilt when the cached OMOPs change): `labs/labs.tsv` (one row per lab of ≥ 5 people: its name as sp_qc gives it, people, % of all results, years, the organisation it is named after and that organisation's share, % without an organisation), `labs/lab_orgs.tsv` (its organisations' shares) and `labs/lab_years.tsv` (the shares per period, years pooled to ≥ 5 people). **Shares and people only, no row counts**, so nothing can be summed against sp_qc's lab-year rows; organisations under 5 people are pooled as "other organisations", or, when together they are fewer than 5 people, left out of that lab's (period's) share base. Per concept, `labs.tsv`: each lab's share of the concept's results, collected from sp_qc's published `_sp_year.tsv` (sum of its shown years), next to its share of all results over the same labs, and the ratio
- `site`: from those tables only, into `/mnt/disks/data/kanta/qc/portal/` (wide layout): `index.html` with two tabs, Concepts (one row per concept: search by name, OMOP id or test name, sort, filters) and Service Providers (two maps of Finland: each region's share of the tests, summed over the service providers whose region it is, and that share against its share of the official population (`--population`, `scripts/sote/data/maakunta_population.tsv`); a table of the regions with their number of service providers, both percentages and their ratio; each region, in the table and on the maps, opens `region/<name>.html`: its service providers largest first, as a pie (the largest 7 in colour, the rest in grey; a slice opens the provider's page) and a table whose names wear the same colours; then one row per service provider); the site says service provider throughout (sp_qc's own texts say lab); `omop/<id>.html` in two tabs, OMOP concept (summary tiles, the audit card, results per year, when the samples are taken, the composition table, and Units and reference ranges) and Service Providers (first the concept's service providers against their share of all results, then the sp_qc card and Service Providers over time); in detail (summary tiles, the audit and lab-report cards with links to every report file, results per year, when the samples are taken (all labs, from sp_qc's `_timing.tsv`: per hour and weekday a dot sized by its share of the results, at the height of its median value vs all), the composition table, then the audit and the lab report drawn in the page with a short "how to read" each (no images): the three checks per test name as small histograms, the decision map, verdicts per test name, where the flagged units came from, the largest flagged groups (KS D is in the composition table); a lab × year heatmap with a measure to pick (median vs national on raw values, × upper or × lower limit, % above / below the lab's own limits, outliers, person jumps, QC fails, outcome mismatch) for the 20 largest labs or the 20 most deviating others, each lab's values as boxes, the reference limits over the years (one small chart per service provider, women and men, upper and lower, the national ones dashed; the ones that changed first) and the reference ranges by service provider (with their changes, e.g. 105 → 97 in 2017) and the flags (searchable): the audit figure and sp_qc's plot pages); `lab/<id>.html` for the `--top-labs` (20) largest service providers only (`--top-labs 0`: all) (its region on a map of Finland, from `scripts/sote/data/maakunta_map.json` (`--map`; drawn from `assets/finland.js`, shared by all pages), its coding-system organisations, all years and over time as stacked shares, and the portal concepts it appears in, with its rows there (the sum of its years shown in sp_qc's `_sp_year.tsv`) and share; every lab stays in the searchable Labs table); `omops.tsv`. Built in `portal.part/` and swapped in; the reports' TSVs are checked again on the way, and a last scan of the whole site (every TSV and every count in the HTML) refuses the build if a count of 1–4 appears.

```
python3 qc_portal.py [--min-rows 5000] [--omop ID ...] [--stage tables|site|all] [--out DIR] [--symlink] [--top-labs 20]
```

Every table adds up: composition rows (pooled row included) and year rows sum to the concept's rows.

## Utils

- **`sort_omop_qc.py`**: re-sorts `src/kanta/engine/data/omop_qc.tsv` in place. Rows with a threshold come first, then the `NA` placeholders. Run it after hand-editing the file; CI checks the order.
  ```
  python3 scripts/qc_checks/sort_omop_qc.py
  ```
